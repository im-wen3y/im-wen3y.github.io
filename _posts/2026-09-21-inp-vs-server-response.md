## 무엇을 몰랐나

API 응답이 느리면 INP도 나빠질 수밖에 없다고 생각했다. INP가 서버 응답 시간이 아니라 **입력 뒤 다음 화면이 그려지기까지의 지연**을 잰다는 걸 몰랐다.

## 개념 정리

INP(Interaction to Next Paint)는 사용자가 클릭·탭·키 입력을 한 뒤 브라우저가 다음 프레임을 그리기까지 걸린 시간을 잰다.

```text
입력 → 입력 지연(메인 스레드가 바쁨) → 이벤트 핸들러 실행 → 다음 paint
       └──────────────── INP가 재는 구간 ────────────────┘
```

- 서버 응답을 기다리는 시간은 이 구간에 들어가지 않는다.
- 서버가 1.5초 걸려도, 클릭 직후 로딩 상태나 선택된 필터를 바로 그리면 INP는 좋게 나온다.
- 반대로 핸들러에서 무거운 동기 작업을 하면 API가 빨라도 INP는 나빠진다.

이건 웹 성능 지표의 정의 문제다. React 자체의 동작과는 관계없다.

## 다시 볼 기준

- 느린 원인이 **네트워크 대기**인가, **메인 스레드 작업**인가?
- 입력 직후 사용자에게 바로 보이는 피드백이 있는가?
